# 10. README guidance

A repository README SHOULD explain purpose, audience, supported platform, setup, build/test commands and limitations. A library SHOULD show a compiling example and API documentation. A CLI SHOULD document installation and invocation; a service should explain deployment, configuration and security; embedded and kernel projects should specify targets, toolchains and safety constraints.

Separate crate READMEs when they have distinct consumers or are published independently. Dual English/Russian documentation is a project choice. A badge row, centered HTML, emoji headings and prescribed README line lengths are not architectural requirements.

Use runnable examples and truthful descriptions. ADRs and project documents explain project-specific boundary choices; the universal handbook should not enforce repository decoration.
