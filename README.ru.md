## 📖 Обзор

**Craftbook** — независимый от конкретного проекта инженерный справочник по Rust: правила проектирования, варианты архитектуры и инструменты. Подходит для библиотек, CLI, серверов, игр, движков, встраиваемых систем, ядер ОС и настольных приложений.

**Это не фреймворк:** здесь нет обязательной иерархии DDD, правила «один тип на файл» или универсального лимита строк. Цель — учитывать реальные ограничения и использовать сильные стороны Rust: владение, безопасные абстракции, явную обработку ошибок и предсказуемый жизненный цикл ресурсов.

## 🎯 Принципы

| Уровень | Значение |
|---|---|
| **MUST** | Корректность, безопасность, обоснованные гарантии и контракты проекта |
| **SHOULD** | Рекомендуемые приёмы Rust с допустимыми обоснованными исключениями |
| **MAY** | Необязательные подходы и инструменты |
| **PROJECT** | Требования к платформам, скорости, совместимости, надёжности и защите |

- 🦀 **В первую очередь Rust:** перечисления, трейты, владение, композиция и модули вместо механического переноса иерархий C#.
- 🧩 **Паттерны по необходимости:** DDD, Hexagonal, CQRS, акторы и подход, ориентированный на данные, необязательны.
- 🛡️ **Явные гарантии:** инварианты, ошибки, условия безопасного применения `unsafe` и жизненный цикл ресурсов.
- 🔬 **Проверка по рискам:** тесты, измерения и ревью вместо произвольных нормативов.
- 🔧 **Автоматизация проверяемого:** Cargo, rustc, rustfmt, Clippy и специальные инструменты для обоснованных требований.

## 🚀 Быстрый старт

Изучи [принципы](#-принципы), выбери подходящий [архитектурный профиль](rust/07-architecture-ddd.md) и используй [пример политики](templates/CraftBook.toml). Следовать руководству можно без установки дополнительных инструментов.

Для экспериментальной нативной проверки политики:

```bash
git clone https://github.com/F000NKKK/Craftbook.git
cd Craftbook
cargo install --path tools/cargo-craftcheck
cargo craftcheck check --config templates/CraftBook.toml
```

Утилита проверяет **конфигурацию политики** и явно заданные запреты прямых зависимостей Cargo Workspace; архитектуру исходного Rust-кода пока не анализирует.

## 🛠️ Инструменты

| Инструмент | Назначение | Состояние |
|---|---|---|
| `cargo fmt` | Форматирование Rust | Стандартный инструмент |
| `cargo clippy` | Диагностика с учётом компилятора | Стандартный инструмент |
| [`cargo-craftcheck`](tools/cargo-craftcheck/README.md) | Проверка политики и прямых зависимостей | Экспериментальный |

```bash
cargo fmt --all --check --manifest-path tools/cargo-craftcheck/Cargo.toml
cargo clippy --all-targets --manifest-path tools/cargo-craftcheck/Cargo.toml -- -D warnings
cargo test --manifest-path tools/cargo-craftcheck/Cargo.toml
```

Конфигурации: [политика самого Craftbook](CraftBook.toml) · [пример политики](templates/CraftBook.toml) · [правила workspace](templates/workspace-lints.toml) · [Clippy](templates/clippy.toml) · [rustfmt](templates/rustfmt.toml) · [шаблон CI](templates/ci.yml).

## 🏗️ Архитектура

Craftbook подбирается под задачу, а не требует одинаковой слоистой архитектуры от всех проектов.

| Задача | Возможные подходы |
|---|---|
| Библиотека или CLI | Связные модули, функции, простая композиция |
| Бизнес-сервис | DDD, Hexagonal, Clean Architecture |
| Система с аудитом и событиями | CQRS, Event Sourcing, обмен сообщениями |
| Конкурентный сервер | Actor Model, каналы, явное владение задачами |
| Игра или симулятор | ECS, структура данных под нагрузку |
| Ядро ОС или встроенная система | `no_std`, RAII, typestate, безопасные границы `unsafe` |

Подходы можно сочетать, учитывая инварианты и компромиссы. См. [главу об архитектуре](rust/07-architecture-ddd.md).

## 👩‍💻 Разработка

Craftbook v2 развивается вместе с реальными Rust-проектами. Изменения глав должны соответствовать примерам и поведению инструментов. Для нативной утилиты есть [отдельный CI](.github/workflows/craftbook-v2.yml); наличие workflow само по себе не означает успешное выполнение.

Переходишь с v1? Используй [руководство по миграции](MIGRATION.ru.md) ([English](MIGRATION.md)). Python-инструменты v1 удалены из `main`; они доступны через теги `v1` и `v2-rc0`.

Craftbook — инженерный справочник, а не формальное доказательство корректности: требования проекта, измерения и ревью остаются необходимыми.

Нативная утилита также поддерживает экспериментальную проверку явно запрещённых прямых зависимостей между пакетами workspace: `cargo craftcheck deps --config CraftBook.toml --manifest-path Cargo.toml`. Используется Cargo Metadata; слои DDD автоматически не навязываются.

Файлы `CraftBook.toml` можно размещать во вложенных папках: локальные настройки переопределяют родительские. Команды `cargo craftcheck check` и `cargo craftcheck deps` запускаются из любой настроенной директории и проверяют её поддерево. [Подробнее](tools/cargo-craftcheck/README.md#hierarchical-configuration).
